# 桌面前端重设计与 HiFi 构建验收

## 本轮改动

- 默认强调色由红色改为冷蓝，暗色界面使用蓝灰分层表面；侧栏、底栏与 Inline 窗口按钮使用较轻的半透明表面。
- 首页四个入口按桌面可用宽度均分，静止封面拼贴不再持续调度动画。最近播放按行阅读，三列、最多三行一页，少量历史不预留空行。
- 最近播放的更多按钮与右键打开真实歌曲操作，点击菜单不会启动歌曲。
- 导航与歌曲行使用标准可聚焦控件，桌面键盘与电视遥控器共用激活路径，长按多选仍只修改选择。
- 下拉菜单从当前项获得焦点，当前值与焦点分别用勾选和边框表达；Escape 取消并返回原控件，页面卸载同步关闭菜单。
- 播放页扩大封面可用空间，左侧元数据对齐封面，歌词占较宽的右侧列，底部播放按钮及进度条居中。低高度与大字体使用紧凑排版。
- 暂停与报错时保留控制栏，仅正常播放且有歌词时才允许超时隐藏。

## Windows 实机交互

使用 computer-use 技能操控最终 Release 应用，窗口尺寸涵盖 1280×720 和用户调整后的约 1352×782：

| 场景 | 观察结果 |
| --- | --- |
| 首页 | 四入口全部可见；一首与多首真实历史均只占所需行数，冷蓝强调色实际生效 |
| 最近播放更多 | 打开下载/歌词操作菜单，当前曲目与播放状态保持 |
| 布局选择器 | 原先 Down 从第一项开始的问题已消失，从桌面端移到电视端，Enter 后整个布局立即刷新 |
| 电视布局 | 顶部右侧独立封面/进度入口可见；设置与菜单使用统一白色焦点环；播放页没有音量及全屏控件 |
| 桌面播放页 | 左侧封面、元数据、底栏无重叠；歌词与队列标签往返可用；返回后继续播放 |
| 普通歌单 | 封面、返回按钮和标题随滚动离开视口；滚动后的歌曲内容在 Inline 顶部安全区域下裁切 |
| 歌曲右键 | 打开歌曲操作菜单，不替换当前正在播放的歌曲 |

第一次 Computer Use 被用户物理 Escape 中断后已立即停止；用户明确回复继续实测后恢复。结束时恢复桌面布局。

- 全量 Flutter：306 通过，2 项因可选外部插件未检出而跳过。
- Flutter analyze：无问题。
- i18n 覆盖检查：无缺失、无过期键。

## HiFi 测试范围

Windows 的 22 项原生离线 CTest 和 14 项 Dart ABI 布局检查通过。最终应用目录的独立诊断程序从无关工作目录运行，确认主/worker isolate 都能加载引擎与桥接，ABI 为 29。

NICEHCK HiFi Audio 被系统枚举为默认设备，驱动接受 44.1/48/96/192/384 kHz 的 16/24/32-bit 独占 PCM 查询。共享与独占打开、静音 WAV 解码检查通过，检查没有启动声音输出或更改系统音量。以上证明构建与驱动协商路径可用，不能代替 DAC 实际聆听、回环测量、插拔或物理 bit-perfect 验收。

当前没有 ASIO 输出后端，Windows HiFi 测试使用 WASAPI。Android USB DAC 测试构建来自独立的原工作区快照，包含尚未提交的 UAC2 改动，使用单独应用 ID；它与本轮 UI 分支并非同一源码版本，不覆盖原工作区或现有正式版。Android 硬件安装与 USB DAC 实测需要连接设备。
