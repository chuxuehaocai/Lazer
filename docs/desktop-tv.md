# 桌面与电视端交互

## 窗口与背景

Windows 和 Linux 可在「界面与布局」中切换 Inline 与经典标题栏，立即生效。Inline 把最小化、全屏和关闭放在右上角悬浮胶囊内：胶囊压在页面之上，画法和移动端导航胶囊一致（玻璃底色 + 背景模糊）；页面从窗口顶边开始绘制，顶部让出胶囊所占的高度作为页面留白而不是独立 Header，因此这段留白随内容一起滚走，滚动内容从胶囊下方穿过。胶囊左侧那一小段是窗口拖动和双击最大化的抓手，页面其余位置的点击仍然归页面所有。正在播放页在桌面布局下同样把顶部这段留白当作抓手，下拉关闭手势从留白下方开始，两者不会抢同一次按下；手机与平板布局不变。经典模式把所有页面背景和图片裁切在独立标题栏下方，图片缩放和模糊不会溢出。

有页面级命令的二级页面（例如「字体自定义」的「恢复默认」）把命令放进胶囊：文字在左，一条淡竖线与三个窗口按钮隔开，胶囊因此向左伸展出这一段；页面头部不再绘制被胶囊盖住的按钮。

胶囊的这段延长一次只属于一组按钮。在「字体自定义」里打开正在播放页时，属于页面的「恢复默认」先把出场动画走完（约 160 ms），胶囊随即才让正在播放页的三个按钮走入场动画（约 260 ms），两组按钮不会同时占着同一个位置；反过来关闭播放器时，两组交换的规则相同。既然是同一个位置，交接就必须串行而不是交叉淡入淡出：谁在退场完全取决于胶囊当前归属哪一组。这条交接只在胶囊确实展开时播放；如果胶囊本来就在收起（例如关闭播放器让它回到页面），收起本身就已经把上一组带走了，此时不会再补一段看不见的交接去拖慢下一组的出现。打开「减少动态效果」时交接直接落地，没有中间帧。

语义色只有一套：`AppleSemanticColors.light / dark`。手机（紧凑）布局只改变间距、导航形态和触控尺寸，不再切换到独立的红强调色 + 纯黑底色板，因此同一个资料库在窗口、平板和手机上看颜色一致；强调色仍可在「配色」里改成随封面或自定义。反色背景（未开背景图）在所有布局统一用暖黑 `#191C23`。

「界面与布局 → 内联窗口胶囊」可调胶囊材质，全部即时生效并持久化：窗口胶囊模糊开关、模糊强度（0–32 px，默认 14）、背景不透明度（20%–100%，默认 72%，与页面头部的默认不透明度一致）。底色默认跟随界面背景色 —— 暗色模式是深蓝 `#191C23`，亮色模式是白 —— 而不是强调色，所以胶囊读起来是窗口的一部分；打开「自定义背景颜色」后才出现调色板，取色写入胶囊底色，关掉即回到界面背景色。关闭模糊时胶囊只画底色，不再运行背景滤镜。

Windows 的浏览背景与正在播放背景均可选择「Windows DWM 云母材质」。原生实现使用 `DWMWA_SYSTEMBACKDROP_TYPE / DWMSBT_MAINWINDOW`，支持 Windows 11 22H2（build 22621）及以上；旧系统或合成不可用时回退到不透明主题底色。全屏进出后重新应用材质，离开云母模式恢复普通窗口背景。其他平台不显示此选项。

「内容不透明度」调整页面文字、按钮和卡片；浏览背景和播放背景各有独立的「背景不透明度」。DWM 的材质由系统合成，背景滑杆通过主题色遮罩调整材质可见程度，内容不透明度不会改变该遮罩。旧版错误使用的遮罩偏好不会迁移成透明文字。

切换桌面、平板、手机、电视布局后，根布局与密度立即更新。电视设备切换到其他布局仍保留遥控器方向键操作。设置仅在相关背景类型下展示动画帧率和质量，移除了内部网格参数说明。

打开正在播放页的入场动画期间暂停背景流动；纯色、图片与云母模式不再提取无用的封面调色板，云母由系统合成。这减少了打开播放器时并行的绘制工作；具体帧率仍取决于设备。

## 导航与播放

桌面界面以冷蓝强调色、蓝灰分层表面和半透明侧栏/播放栏组成。首页四张入口在桌面宽度下均分，封面拼贴保持静止；最近播放按行阅读，最多三列、三行一页，少量记录只占实际行数。更多按钮和右键打开曲目操作，不会启动播放。桌面导航、歌单和歌曲行可用 Tab 与 Enter，电视保留方向键与确认键。

设置选择器把当前值的勾选与键盘焦点边框分开。展开后焦点从当前项开始，Escape 取消并回到原控件；离开设置页面时菜单同步关闭。菜单宽度限制为 320 逻辑像素，长列表自动滚动至当前项。

正在播放页给歌词保留较宽的阅读区域，封面与元数据共用左侧对齐线，播放按钮和进度条在窗口中居中。低高度或大字体时改用紧凑封面与可滚动信息。桌面布局在存在歌词时按空闲倒计时隐藏控制栏，播放与暂停一视同仁：暂停不再把控制栏钉在画面上，点一下画布即可重新唤出；播放错误是例外，会恢复控制栏以便重试。触屏的紧凑布局在暂停时保留控制栏，因为它只有顶部小摘要这一个唤出入口。倒计时按页面实时状态对账：在切歌加载歌词、面板或弹窗打开、拖动窗口等「此刻不允许隐藏」的窗口里耗尽的那一次倒计时，会在重新允许隐藏后立即重启，不再需要下一次点击才会消失。

再按一次「歌词」（或 L）收起歌词栏：封面与元数据沿一条 Apple 弹簧曲线移到画布正中，并长到画布高度允许的尺寸（上限 720 逻辑像素）；恢复时同一条曲线把它们送回左栏。弹簧由 `AnimationController.unbounded` + `AppleSpring` 驱动，动画中途反向会带着当前速度和位置重新瞄准，而不是从两端之一重新开始；歌词画布在淡出期间保持自身尺寸，只在 `TickerMode`、焦点、语义和命中测试上立即退出，因此逐帧的重排只发生在封面一侧。

电视顶部导航右侧的歌曲封面是独立的「正在播放」入口，外圈表示播放进度。方向键可以在导航、封面和内容间移动，遥控器确认键打开播放器。头像、歌曲和其他操作沿用白色焦点环；头像的焦点环保持圆形。

当前音乐平台声明 `listenTogether` 能力时，桌面播放器头部和电视顶栏右侧显示「一起听」，可创建房间或输入邀请码加入。平台切换后入口随能力更新，不支持的平台不显示入口。桌面侧栏不再保留该入口。

桌面歌单的返回按钮、封面、说明和播放操作都属于列表顶部内容，滚动歌曲时一起滚出视口，不再保留额外固定工具条。

## 歌词窗口

- 悬浮歌词未锁定时，拖动文字或左侧拖动柄可移动窗口。文字以外的透明区域不拦截其他应用的鼠标操作。
- 锁定悬浮歌词后，整个窗口允许鼠标穿透，可从主窗口的歌词设置解除锁定。
- 桌面歌词的文字始终允许鼠标穿透，只在左侧拖动柄接受拖动。拖动后保存坐标，下次启用时恢复；移除显示器后会将位置限制在最近显示器的工作区内。
- Windows 原生交互区域使用 Flutter 的逻辑坐标并按窗口 DPI 换算。桌面歌词拖动不会抢占当前应用的焦点。
- 两种歌词窗口使用低透明度柔和阴影，避免多层高不透明度阴影叠成黑色底块。
- 歌词窗口不跟随焦点节流：Windows 在别的窗口获得焦点时把本窗口报告为 `inactive`，歌词仍按 60 fps 推进文字动画；只有窗口被隐藏或引擎暂停时才释放 vsync 回调。桌面歌词窗口是鼠标穿透的，几乎永远拿不到焦点，按焦点节流会让它长期停在 20 Hz 的位置包刷新上。

## 验收场景

自动回归测试位于 `test/adaptive_chrome_regression_test.dart`，覆盖遥控器确认、独立播放入口位置、歌词鼠标区域、锁定行为，以及歌单顶部随列表滚动。

Windows 实机验证应检查：在桌面拖动歌词后重新启用、跨不同 DPI 显示器拖动、点击歌词周围的桌面图标、锁定悬浮歌词后点击文字下方的其他应用。电视应检查方向键往返头像与导航、打开正在播放后返回焦点，以及切换支持/不支持一起听的平台。

`test/interface_preferences_test.dart` 与 `test/window_backdrop_test.dart` 覆盖布局即时更新、透明度持久化与隔离、Windows 平台限制、材质失败回退、全屏重应用和过期响应。实机还需对照浅色/深色桌面背景检查 Mica，并分别验证 Inline 与经典模式下的图片边界。
