# 移动 UI 恢复与第三轮审计（2026-11-18）

## 基线与恢复范围

以 `v2.0.210`（`0165aaed5da3cab3b402f53251e56253ec5867a4`）对照手机视觉，
在当前 `66da483` 及既有未提交修复上增量修改，没有回退版本号、音频引擎、
插件 API、网络源或持久化逻辑。修改前工作区备份位于
`.git/codex-backups/before-mobile-restore-20261118-100044.zip`。

回退感来自两处叠加：桌面改版 `781272e` 改动了全局语义色；上一轮未提交的
响应式统一又将手机的导航胶囊与圆形歌曲入口改成两层迷你播放栏。
首页卡片、最近播放排序和设置密度也受桌面样式调整影响。

- 恢复手机红色强调色、黑灰语义色与暖黑浏览底色，独立保存手机/桌面色板。
- 手机底部恢复同一行的胶囊导航和 48px 圆形封面进度入口。
  不恢复历史透明的 1×1 播放器；位置更新只重绘圆环，隐藏时断开进度监听。
- 恢复手机最近播放三行列序、66px 基准卡高、8px 间距、快捷卡字阶及渐变、
  方形封面拼贴与排行榜倾斜构图。拼贴保留当前静态实现，不重新引入常驻动画。
- 恢复手机设置分类宽度、说明、行高及返回栏间距；保留当前设置项与行为。
- 完整移动播放器的 `ArtworkLyricsLayout` 与 2.0.210 一致，保留其布局及当前
  播放、歌词、背景、暂停和生命周期修复，仅接入正确的手机主题。
- 保留现有统一断点、界面缩放、宽屏桌面、TV、字体、插件皮肤、自定义配色、
  seek 取消处理、页面状态保持及背景帧率策略。

## Computer use

使用 `computer-use` 的 `@oai/sky` 操作 Windows 原生 profile 窗口。
入口为真实 `LazerApp`，窗口为 390×800 逻辑像素；只替换测试数据与音频后端，
使用生成的本地封面、48 首合成歌曲和 120 行逐字歌词，偏好及队列存储隔离。

实际检查了首页、圆形歌曲入口、完整播放器、封面切换歌词、控件自动隐藏、
返回首页、设置分类及设置详情。首次窗口检查发现 `AppShell` 自建主题覆盖
根手机主题，修复并新增集成回归后，重新构建确认红色圆环与手机卡片显示正确。

最终第三轮构建再次用鼠标检查：圆形入口进入播放器，下一首从 `Evening light 0`
变为 `Evening light 1`，暂停后按钮变为播放；“更多 → 睡眠定时 → Escape”
返回原播放器并保留歌曲与暂停状态。返回首页后当前歌曲高亮同步，设置分类说明、
详情页返回栏、红色开关和滑块显示正常。运行日志未出现 Flutter 异常。

复现：构建 `tool/benchmarks/player_open.dart` 的 Windows profile 版本，设置
`LAZER_UI_REVIEW=1` 和 `LAZER_BENCHMARK_WIDTH=390` 后启动可保持交互检查窗口。
此模式不播放真实音频、不需要账号；详见 [基准说明](../tool/benchmarks/README.md)。

## 第三轮修复与重构

| 触发场景 | 复现的问题 | 修复 |
| --- | --- | --- |
| 歌词模式从 More 打开睡眠定时、保存封面、添加歌单 | More 退出先重启隐藏计时，子弹层还在时控件消失 | More 返回 action 并等待其完成，统一 `try/finally` 恢复隐藏；独立长按保存、队列、评论同样保护 |
| More 退出动画期间再次点击旧控件 | 旧回调弹出新子路由，甚至传入错误类型结果 | 单次交接标记、mounted 和当前路由检查；覆盖取消及迟到插件失败 |
| 串行插件权限弹窗中重复点击已关闭弹窗的允许/拒绝 | 前一次响应误完成下一权限请求 | 每次请求只能响应一次，同时验证根/弹窗挂载状态与当前路由，不改变权限授予模型 |
| 在宽窗口强制手机布局 | 部分卡片仍使用桌面密度与专辑列 | `AppThemePresentation` 传递已解析的布局，主页/共享卡片/设置读取同一结果 |
| 外接键盘或窄桌面进入播放器 | 圆形入口不能通过 Tab/Enter/Space 操作 | 等尺寸 TextButton，保留单个语义入口与焦点反馈，隐藏时不可抢焦点 |
| 扫描中卸载整个 Navigator | `popped` 未完成，扫描进度定时器仍运行 | `completed` 同样取消扫描及定时器，然后释放 notifier |
| 网络目录切换且新请求未返回 | 旧目录歌曲仍可点击并以新目录会话提交 | 换路径即清旧列表；同路径刷新继续保留已有内容 |
| 横向卡架翻页及同帧布局变化 | 翻页缺少语义名称，尺寸刷新可能重复排队 | 增加本地化名称、隐藏按钮退出语义树，合并同帧刷新 |

上述问题均有失败复现或交互证据及对应回归。文字放大继续采用有界文本测量缓存，
手机快捷卡在大字体下增加必要高度，常规字体保持基线尺寸。
四语文案同步，并清理已无消费者的旧蓝色/帧率说明。

## 审计覆盖与检查边界

人工检查覆盖主题和根 Navigator、主壳与保留页面、导航/播放栏、完整播放器
及弹层/路由手势、主页/歌曲/排行榜卡片、设置详情、网络浏览会话、本地扫描
所有权、插件市场所有权和异步结果。并复核已有桌面/悬浮歌词、滚轮惯性、
背景/歌词节拍等回归，不改动本轮未发现确定缺陷的代码。

资源扫描遍历 337 个 Dart 文件，初次 8 个、最终 7 个启发式提示：设置的 notifier 在 dispose
释放；媒体时钟和 station 定时器由 close 释放；背景 ticker 由基类销毁调用
unscheduleTick；控制台和插件定时器均有取消/失效路径。提示不等于已证实缺陷，
没有用“扫描无告警”代替生命周期验证。

## 窄屏渲染抽样

第三轮最终代码在 Windows profile、390×800、144Hz 下独立运行。每种背景四次，
每次包含进入播放器和随后 1.6 秒；各模式首次打开标记为 cold，但不代表清空
着色器缓存或重启进程。[原始数据](validation/ui-round3-mobile-2026-11-18.json)。

| 背景 | 帧数 | Build P95 范围/ms | Raster P95 范围/ms | 最差 Raster/ms | 超过 6.94ms 预算的帧 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 流动 | 911 | 0.133–0.152 | 1.667–2.727 | 12.362 | 8 |
| 静态 | 600 | 0.098–0.112 | 1.793–3.473 | 15.392 | 7 |
| Windows Mica | 604 | 0.101–0.110 | 0.313–0.352 | 0.613 | 0 |

共 2115 帧，其中 15 帧的 build 或 raster 超预算。没有因 P95 较低而忽略偶发长帧。
这些是本机合成数据的引擎耗时，不是 Android/iOS 硬件帧率或端到端延迟，
也不据此声称相对旧版本有性能提升；联网图片、音频解码和不同 GPU 需另测。
